# 验证计划：可达性信息能否帮助做决定？

状态：计划，未招募、未执行，没有用户研究结果或 A/B 提升数据。

## 假设和风险

H1：显式出行预算与来源标记能帮助用户更快筛出可行候选，减少无目的的外部信息搜索。

反向风险：用户可能把历史 SNAP 误读为当前承诺，把模型分钟误读为准确 ETA；字段更完整也可能增加不恰当的信任。这些理解风险比单纯提高点击率更重要。

## 首轮形成性研究

招募 5–8 名有 Philadelphia 食品购物经验的成年人；包含有车/无车使用者，区分哪些场景被模型排除。无需收集 SNAP 领取证明、住址或财务信息。自愿参与，可退出，告知使用历史数据、操作不代表真实购买建议。

采用主持式任务测试，约 25–35 分钟。若比较原项目地图与新版，分组交叉安排先后顺序，用难度相近但地点不同的任务减少学习效应。小样本主要寻找问题，不用于宣称统计显著。

任务：

1. 从 University City 查找 15 分钟驱车预算内的历史 SNAP 超市，解释选择原因。
2. 找到另一候选并比较来源、联系方式、未知信息。记录是否需要外查，不把合理核验算作失败。
3. 说明 Nearby 与 Drive 的区别；读出“历史 SNAP”和时间估算不能保证什么。
4. 收藏、返回 Saved、改变预算，解释为什么有的收藏不在当前筛选结果中。
5. 在 Area insights 中找一个区域，判断“零条记录”能否推出“没有店”。
6. 对一条可疑信息做本地标记，解释它是否真的被提交给了商家。

主持人记录完成情况、开始/结束时间、求助次数、误解、外查原因以及原话。实际到店不属于本轮任务。

## 指标定义

| 指标 | 明确口径 | 当前可用性 |
|---|---|---|
| 任务成功率 | 正确选出满足任务约束且能解释限制的完成任务数 / 尝试任务数 | 人工判定；尚无观测 |
| 决策耗时 | 从主持人读完任务到说明选择理由的秒数，分别报告成功/失败样本 | 人工计时；尚无观测 |
| 历史状态理解率 | 正确说明历史记录不等于当前接受的参与者数 / 被问及者数 | 人工提问；上线前护栏 |
| 模型理解率 | 正确区分模型 ETA 与实时导航的参与者数 / 被问及者数 | 人工提问；上线前护栏 |
| 会话详情参与率 | 有 place_detail_open 的已同意记录会话数 / 已同意记录会话数 | 本地事件可辅助，分母需研究者记录 |
| 会话收藏参与率 | 有 save_place 的已同意记录会话数 / 已同意记录会话数 | 是意图代理，不是到店转化 |
| 空结果率 | count=0 的 search_results 事件数 / 全部 search_results 事件数 | 500ms 防抖，仅代表搜索交互，不含所有页面曝光 |
| 外部导航意图率 | 有 directions_click 的会话数 / 有详情打开的会话数 | 不能推断导航成功、到店或交易 |

事件开关位于 Product study，默认关闭；开始后记录 session_start、搜索结果数、筛选、起点变更方式、详情类别、收藏、区域浏览、导航点击、纠错等。无原始搜索词、坐标、姓名或稳定用户标识。不后台上传；关闭开关保留已记录事件，可手动导出 JSON。每个受试者新开标签页；重复开关的 session_start 不应被当作不同用户。

局限：没有曝光埋点、有效停留判定、独立用户去重或 task_start/task_end，所以不能声称已经测量了 POI 有效访问渗透、完整漏斗或留存。记录不是实验分流系统。

## 决策规则（预先拟定，不是测试结果）

- 若任何参与者把历史状态或估算时间当作保证，先修订文案和展示，再复测。
- 如果多数任务阻塞来自来源缺失，优先做数据补全/核验，而不是扩大入口曝光。
- 如果核心需求来自无车场景，先补步行/公交模型，再评估当前时间预算的价值。
- 若用户能正确理解但比较负担高，再实现双店对比并针对性复测。

首轮只报告原始计数、个案与问题严重性。要做量化上线实验，须先定义合格曝光、样本量、最小可检测效应、随机化单位与护栏；本原型不具备这类业务实验结论。
