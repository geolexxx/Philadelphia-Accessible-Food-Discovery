# 产品说明：从“哪里缺食物”到“我能去哪家店”

状态：可运行研究原型；尚未经过真实用户验证。日期：2026-09-20。

## 1. 产品问题

原空间分析面向区域性食品获取问题。新原型切换到一个具体决策：用户从某个位置出发，在有限时间内找到一个值得进一步核验的食品购物地点。

假设的目标用户是需要比较附近食品商店、部分关心 SNAP 的 Philadelphia 居民。这个用户定位不是已完成的访谈结论，需要验证。当前驾车模型主要服务能使用汽车的人；无车家庭是重要的未覆盖人群，不能把原型宣传为普适的食品可达性解决方案。

Job to be done：当我计划一次食品采购时，帮助我筛出符合出行约束的候选店，知道哪些信息可信、哪些仍需确认，然后留下一个明确的下一步。

## 2. 决策链

出发点与预算 → 发现候选 POI → 查看类别、来源与缺失信息 → 对比行程 → 收藏或外部导航 → 到访前核验。

本次实现停在“决策与行动入口”，并没有到店、支付或履约数据。

## 3. MVP 需求与验收

| 优先级 | 已实现需求 | 验收口径 |
|---|---|---|
| P0 | 名称、地址、ZIP 搜索；类别和历史 SNAP 筛选 | 筛选条件取交集；未知状态不被当作不接受 SNAP |
| P0 | 出发点、时间预算、驱车路径 | 单行道生效；无有效路线不出现虚构 ETA；切换出发点清空旧路线 |
| P0 | 来源明确的 POI 详情 | 显示数据年代、缺失字段、模型限制及待核验关联 |
| P0 | 收藏和行动入口 | 收藏本地保存；外部导航须由用户点击触发 |
| P1 | 直线距离模式 | 明确不是步行路线；不混用 road distance 和 direct distance |
| P1 | AOI 区域观察 | 用点落区归属汇总；说明这是观察到的供给，不是真实覆盖率 |
| P1 | 数据纠错、研究导出 | 标记仅本地保存，不能声称已提交给商家；事件默认关闭 |

## 4. 关键取舍

**可解释模型先于不可靠的精确时间。** 原项目提供驾车网络，缺少完整步行/公交条件。先用方向性最短距离与明确的时间假设，拒绝把直线距离伪装成步行导航。25 km/h + 5 分钟只是演示参数，未校准。

**保守匹配优先控制误合并。** 同名分店或相近商户错误合并会污染属性。当前只关联标准化名称、地址相等且相距不超过 120 m 的唯一候选。9 对仍保留待人工核验状态，其他重复可能存在。后续应该用人工标注集比较 precision / recall，而不是单追求“去重率”。

**质量先显露，再补齐。** 6 字段完整度不等于可信度。没有电话或营业时间时明确缺失，不补造。历史 SNAP 状态不当作当前承诺。

**区域视图提供上下文，不给地区贴标签。** 只展示本快照供给数量。不把零记录解释成“没有店”，也不基于收入、种族等变量生成商圈价值分。

## 5. 与 TTLS POI PM 的联系

这里复用了用户提供的业务材料中的问题类型，不是复刻内部产品，也不是声称参与过 TikTok 项目：

- 信息建设：来源对齐、字段完整度、过时信息和纠错流程，对应菜单/官网等决策信息的供给问题。
- 可达性与 Plan Your Visit：把“多远”翻译成有边界的行程估算，辅助“去得成”的判断。
- 核心行动点：让查看、收藏、核验路线有清晰入口，并设计各自的观察指标。
- POI 与区域：用地点与区域关系支撑探索；后续才考虑经验证的商圈或目的地区域。

## 6. 下一阶段，而非已完成成果

1. 数据可信度：人工核验 9 对关联；分层抽样核查重复、坐标、类别和历史状态。当前把 USDA Large Grocery 归入 Supermarket 是展示层映射，不是新证据。
2. 用户验证：执行研究计划，判断用户是否理解历史标签和时间估算，再决定是否继续。
3. 出行覆盖：补充步行、公交和门店入口数据，验证无车用户场景；这可能比增加更多筛选器更重要。
4. 体验改进：若研究确认比较困难，再做双店对比；若信任不足，优先更新关键属性和来源日期。
5. 正式服务前：补齐数据授权链、生产监控、更新机制、隐私说明和模型校准。没有这些条件不应对外宣称可靠导航或当前 SNAP 店铺推荐。
